# ShopCoursework

Учебный интернет-магазин на ASP.NET Core MVC. В проекте есть каталог товаров, корзина, оформление заказов, личный кабинет с адресами доставки и панель администратора для управления товарами и вариантами одежды (SKU, размер, цвет и остаток).

## Технологии

- .NET 8 / ASP.NET Core MVC
- Entity Framework Core 8
- SQLite
- ASP.NET Core Identity
- Bootstrap 5

## Требования

- .NET SDK 8.0.426 или совместимая версия .NET 8
- Инструмент `dotnet-ef` версии 8.x для создания базы данных из миграций

## Запуск

Из корня проекта выполните:

```bash
dotnet restore
dotnet tool install --global dotnet-ef --version 8.0.0
dotnet ef database update
dotnet run
```

Если `dotnet-ef` версии 8 уже установлен, повторно устанавливать его не нужно. После запуска откройте URL, указанный командой `dotnet run`.

База SQLite по умолчанию создаётся в файле `shop.db` в корне проекта. Строка подключения задаётся параметром `ConnectionStrings:DefaultConnection` и может быть переопределена через переменную окружения `ConnectionStrings__DefaultConnection`. В базу миграцией добавляется небольшой набор демонстрационных товаров. Файл базы данных не хранится в Git.

## Настройки

В `appsettings.json` задаются название магазина и формат валюты:

```json
"Store": {
  "Name": "ShopCoursework",
  "CurrencyCode": "RUB",
  "Culture": "ru-RU"
}
```

`Name` отображается в шапке сайта и заголовке вкладки. `CurrencyCode` задаёт код валюты для форматирования в корзине, а `Culture` — локаль отображения цен. При смене валюты укажите соответствующие друг другу код валюты и культуру.

Параметр `AdminEmail` должен содержать email учётной записи, которой нужно выдать роль администратора. Чтобы настроить администратора в чистой базе:

1. Запустите приложение и зарегистрируйте учётную запись с нужным email.
2. Остановите приложение и укажите этот email в `AdminEmail` в `appsettings.json`.
3. Запустите приложение снова — при старте пользователю будет назначена роль `Admin`.

Не публикуйте реальные адреса и секреты в общедоступной конфигурации. Для локальных переопределений используйте User Secrets или переменные окружения ASP.NET Core Configuration.

## Основные возможности

- просмотр каталога и добавление товаров в корзину;
- оформление заказа и просмотр заказов в личном кабинете;
- регистрация, вход, смена пароля и редактирование профиля;
- добавление и удаление адресов доставки;
- выбор адреса при оформлении заказа с сохранением его снимка в заказе;
- оплата наличными при получении без подключения платёжного сервиса;
- добавление, изменение и удаление товаров в панели администратора;
- управление вариантами товара, SKU и складскими остатками;
- проверка и списание остатков при оформлении заказа;
- просмотр заказов в админке, переходы статусов и отмена с возвратом остатка;
- проверка antiforgery-токенов для POST-запросов.

Администратор управляет вариантами товара на странице «Варианты и остатки». У каждого SKU должен быть уникальный код, размер, цвет и неотрицательный остаток. Цена берётся у базового товара. При оформлении заказа сервер повторно проверяет и атомарно списывает остаток; клиентская корзина не является источником истины по наличию. В заказе сохраняются снимки названия, цены, SKU, размера, цвета и выбранного адреса доставки на момент покупки.

В админке заказы проходят этапы «Новый» → «Подтверждён» → «Отправлен» → «Доставлен». После доставки администратор отдельно отмечает получение оплаты наличными. Новый или подтверждённый заказ можно отменить; отмена атомарно переводит его в статус «Отменён» и возвращает зарезервированные варианты на склад. Повторная отмена и отмена уже отправленного или доставленного заказа не выполняют переход и не меняют остатки.
